# agent-context Specification

## Purpose
在不自动删除用户历史记录的前提下，为每次模型调用选择有界、协议合法且符合可用 token 预算的近期上下文，并在服务端仍报告超限时进行受控恢复，避免重复远端操作和不可解释的智能体失败。

## Requirements

### Requirement: 最近六十条持久消息窗口
系统 SHALL 在每次模型调用前从当前对话选择最近最多 60 条已持久化消息记录，包含工具消息、shell 事件消息（`source=shell_event`，即用户手动执行的命令记录）和本轮已持久化内容；数量窗口不是 60 轮问答。超出窗口的记录 MUST 仅退出请求上下文，仍保留在历史中供查看和手动删除；MUST NOT 通过长期摘要重新带回窗口外的历史。

#### Scenario: 历史超过六十条
- **WHEN** 对话中已有超过 60 条数据库消息记录并发起模型调用
- **THEN** 候选历史只来自最新 60 条，旧记录仍能分页查看，数据库没有发生自动删除

#### Scenario: 一轮任务多次调用模型
- **WHEN** 同一任务执行工具后再次调用模型
- **THEN** 新增工具结果先持久化，再重新应用 60 条窗口与 token 预算，而不是无限追加首次构造的请求

#### Scenario: Shell 事件消息纳入窗口计算
- **WHEN** 对话历史中包含 `source=shell_event` 的人工命令记录
- **THEN** 这些记录计入 60 条窗口上限，与 AI 消息（`source=ai`）共享同一窗口，不被单独排除或特殊对待

### Requirement: 请求总 token 预算
系统 MUST 在发送前同时预算系统指令、当前连接状态、历史、工具定义及消息结构开销，并预留输出及推理消耗空间和安全余量。60 条仅为数量上限，实际带入记录 SHALL 可以更少；估算值和未知模型配置 MUST NOT 被宣称为精确容量保证。

#### Scenario: 少于六十条仍超限
- **WHEN** 十条长工具输出已超过配置的输入预算
- **THEN** 系统在调用前缩减请求历史或工具输出投影，界面提示上下文已缩减，原始持久历史不因预算裁剪而改写

#### Scenario: 最小请求也无法容纳
- **WHEN** 系统指令、当前用户问题、工具定义与必要最新执行结果经允许缩减后仍无法满足预算
- **THEN** 系统不发送明知超预算的请求，结束当前生成并明确提示缩短输入、调整上下文配置或更换模型，不执行新的远端命令

### Requirement: 工具消息完整性
系统 MUST 将携带工具调用的 assistant 消息及对应全部工具结果视为不可拆开的协议组，校验调用标识完整且无重复；窗口边界残组必须整组排除，不得向前读取超过 60 条补组、补造模型调用或伪造成功结果。系统指令和当前任务的有效问题不得被静默丢弃。

#### Scenario: 窗口从工具结果中间开始
- **WHEN** 最新 60 条的起点落在某次工具调用的结果中间
- **THEN** 系统不发送孤立结果，排除不完整组后其余上下文仍满足目标协议结构

#### Scenario: 多个工具结果缺少一项
- **WHEN** assistant 记录包含多个调用标识而历史只包含部分结果
- **THEN** 该不完整组不进入模型请求，不能仅凭相邻存在一条工具消息就认定合法

### Requirement: 有界工具输出与来源标记
系统 SHALL 对提交模型的长终端及工具输出施加独立长度预算，并标注截断、命令来源、执行状态和必要定位信息；MUST 将远端内容作为不可信数据，不从输出中的文本指令获得新的执行权限，也不得自动发送 SFTP 文件正文给模型。

#### Scenario: 长输出缩减
- **WHEN** 某次命令输出较长，预算只允许保留部分内容
- **THEN** 模型收到带明确截断标记的结果，界面不会将省略内容解释为执行失败或完整结果，原始记录仍按历史存储上限保留

### Requirement: 上下文超限的单次恢复
只有明确识别为上下文超限的响应 SHALL 触发缩减后的恢复；同一用户任务最多一次。恢复 MUST 使用固定历史快照和已持久化工具结果，只重试模型调用，不重新提交用户消息、不重跑工具、不更换连接、不循环重试。普通鉴权、网络、协议错误及输出达到长度上限不得混同处理。

#### Scenario: 工具执行后模型拒绝上下文
- **WHEN** 远端命令已执行且结果已落库，后续模型调用明确报告上下文超限
- **THEN** 系统只以更小的同一快照再次调用模型，远端命令执行次数不增加，用户消息不重复落库

#### Scenario: 恢复仍然失败
- **WHEN** 本任务已经恢复一次，再次出现超限
- **THEN** 系统停止本任务的模型生成，显示上下文超限及可操作建议，保留历史、实际执行结果和可用终端，不再自动重试

#### Scenario: 已显示部分失败回答
- **WHEN** 失败尝试已向界面输出部分文本后才报告超限
- **THEN** 界面明确标记该尝试已中断并替换其未完成回答，恢复结果不与失败片段拼接成一条貌似完整的回答
