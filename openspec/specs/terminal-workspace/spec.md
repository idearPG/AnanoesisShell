# terminal-workspace Specification

## Purpose
提供面向 Linux 运维的多连接智能终端工作区，使同一服务器的多次连接保持独立，并让人工 Shell 与 Agent 在每个连接内共享终端、执行环境和可追溯的操作记录，避免跨连接串扰。

## Requirements

### Requirement: 每个连接实例独立且连接入口每次新建
系统 SHALL 使每个连接实例（顶层 tab）拥有独立的连接、输出、输入草稿、审批及传输状态，切换 tab、访问设置或切换模式 MUST 保留未关闭实例的全部状态。新建实例的入口有两个：服务器列表的“连接”与工作区 tab 栏的“+”（以当前 tab 的主机新建）；两者都是**必新建**语义（用户修订：同一服务器每次连接都必须是独立实例，各自拥有独立终端会话、Agent 上下文与人工审批，互不影响；曾短暂采用过“已有 tab 则跳转复用”语义，因迫使多次排障共享同一会话而撤销）。跨页回到既有工作区由“工作区导航回跳”入口承担，不靠连接按钮复用。MUST NOT 因页面切换而断开任何实例。

#### Scenario: 同一服务器多开
- **WHEN** 用户在已有服务器 A 的 tab 时点击 tab 栏“+”（或先切到主机页再点“+”）
- **THEN** 出现 A #1、A #2 两个独立 tab，任一实例的目录切换和关闭均不改变其他实例的运行状态

#### Scenario: 列表连接每次新建独立实例
- **WHEN** 服务器 A 已有工作区 tab，用户从服务器列表再次点击 A 的“连接”
- **THEN** 新建一个全新的 A 实例 tab 并进入它；既有 tab 的连接、终端历史、待审批队列均不受影响

#### Scenario: 后台连接继续工作
- **WHEN** 用户从正在输出的 A #1 切换到 A #2 或设置页后返回
- **THEN** A #1 未因页面切换断开，其输出、草稿及所选模式仍保留，后台待审批在所属 tab 显示标记；终端历史（含用户输入回显与审批留痕）在切走期间照常写入 A #1 自己的终端缓冲区，切回后完整可见且尺寸正常，MUST NOT 以清空/重置缓冲区的方式隔离 tab 历史

### Requirement: 工作区导航回跳
存在至少一个未关闭的工作区 tab 时，侧栏 SHALL 显示“工作区”入口；点击后 MUST 回到最近一次活跃查看的 tab（路由 `/workspace/<id>`），MUST NOT 新建连接或丢失既有 tab。当前活跃 tab 被用户登记为“最近活跃”；若该 id 已不存在（被关闭）则回退到剩余 tab 的第一项；关闭当前 tab 时“最近活跃” SHALL 回退到剩余最后一条或清空。无任何 tab 时侧栏不显示该入口，硬刷新后（连接已断）不持久化“最近活跃”指向。

#### Scenario: 切页后回到工作区
- **WHEN** 用户在 tab A #1 活跃时切到服务器列表或设置页，再点侧栏“工作区”入口
- **THEN** 回到 A #1 所在路由，A #1 的连接、终端历史与其他 tab 状态均不变，tab 栏无重复项

#### Scenario: 最近活跃 tab 已关闭
- **WHEN** “最近活跃”指向的 tab 已被关闭，用户点击侧栏“工作区”入口
- **THEN** 回跳到剩余 tab 中的第一项，不白屏、不报错

### Requirement: 同终端双输入模式
系统 SHALL 在同一终端工作区连续呈现人工命令、自然语言问题、AI 解释、命令审批和执行输出；Shell 与 Agent SHALL 仅改变输入处理模式，不创建第二套可见聊天页面或重建连接。

#### Scenario: 连续查看人工与智能体操作
- **WHEN** 用户先执行 Shell 命令，再切到 Agent 提问，然后切回 Shell
- **THEN** 三次操作出现在同一工作区的连续记录中，既有输出不被隐藏替换，模式切换不向远端发送自然语言或界面卡片内容

#### Scenario: 交互程序占用终端
- **WHEN** 用户在终端运行 vim 或 top
- **THEN** 终端保持原有光标与全屏交互能力，AI 卡片不破坏终端屏幕，自动命令不得进入该程序的输入流

#### Scenario: 键盘操作和焦点保持
- **WHEN** 用户使用键盘切换连接、修改审批或操作文件队列，同时后台产生输出
- **THEN** 操作控件可聚焦且状态不只依赖颜色，异步输出不抢焦点，tab 导航不截获终端内按键，关闭或取消后焦点回到有效控件

#### Scenario: 回合结束自动落位输入提示符
- **WHEN** Agent 回合结束（回答完成、发生错误、被用户停止、审批被取消而终结、触达工具轮次上限）且该 tab 处于 Agent 模式
- **THEN** 终端自动换行打出 `❯` 输入提示符并把光标停驻其后，用户无需先按键即可直接键入下一个问题；若提示符空行尚未键入时有异步终端输出到达，系统先清除该空提示行再写输出，输出后用户键入时提示符仍在新行以 `❯` 开头补打，输入与输出永不拼在同一行

### Requirement: 持久执行环境与输入所有权
同一连接内获准执行的 Agent 命令及只读工具 SHALL 使用该连接的持久 Shell，继承实际工作目录和环境。系统 MUST 在命令执行和输入权状态可靠时才注入命令；不得把独立 exec 的输出合并显示当作共享环境。人工输入活动使终端进入忙碌态时，获准命令 MUST NOT 被拒绝，SHALL 排队等待输入权恢复后自动派发；忙碌态在用户停手超过静默自愈时限（从最后一次按键起算，连续按键重置计时）且无前台命令运行证据时 SHALL 自愈：先清除可能残留的半行输入再归还输入权，打破"拒绝提交→无完成帧→永久忙碌"的死锁。有前台命令或交互程序运行证据时 MUST NOT 触发自愈清行。MUST NOT 凭静默时间猜测**在飞命令**已完成（命令完成仍以可靠完成帧为唯一证据）；静默自愈仅用于归还**空闲终端**的输入权，两者语义 MUST 区分。

#### Scenario: 人工切目录后交给智能体
- **WHEN** 用户在 A #1 执行 cd /var/log 后要求 Agent 列出当前目录内容
- **THEN** Agent 在 A #1 的 /var/log 中操作，A #2 的目录不受影响，结果在 A #1 呈现

#### Scenario: 半行输入或状态未知
- **WHEN** 人工输入尚未提交、交互程序占用终端，或系统无法可靠判断 Shell 状态
- **THEN** 自动命令不被立即注入而是排队，界面提示处理已有输入、退出程序或恢复终端集成；在飞命令的完成判定不凭静默时间猜测

#### Scenario: 终端集成不支持
- **WHEN** 当前 Shell 无法建立受支持的命令边界与状态集成
- **THEN** 人工终端和可用的 SFTP 仍可使用，界面明确禁用自动命令执行，不隐式新建 exec 执行

#### Scenario: 停止回合后键盘活动不再卡死获准命令
- **WHEN** 用户停止 Agent 回合后在终端敲过按键（含未回车的半行）再批准 Agent 命令
- **THEN** 该命令不被以忙碌状态拒绝而是排队；用户停手超过自愈时限后，终端残留半行被清除、输入权归还，排队命令自动派发执行，Agent 不再出现"重复思考不执行"

#### Scenario: 前台程序运行期间不自愈清行
- **WHEN** 用户在终端运行 top、vim 或嵌套 Shell 等前台程序（有命令开始运行的帧证据）期间存在排队的获准命令
- **THEN** 自愈清行不被触发（Ctrl-C 不会杀死用户的前台程序），排队命令继续等待，直到该程序退出、终端回到空提示符后输入权才归还并派发

### Requirement: 连接级授权与事件归属
系统 MUST 在服务端将输入、运行、活动对话选择、审批、传输及订阅绑定到具体连接实例及其控制权限，拒绝不匹配或过期的请求；MUST NOT 仅依据服务器相同或当前前端选中 tab 判定归属。历史查询和删除属于应用级管理操作，不要求已销毁的连接凭证，也不得赋予历史任何执行权。

#### Scenario: 同主机不同连接请求混用
- **WHEN** A #1 的调用携带 A #2 的审批、运行或传输标识
- **THEN** 服务端拒绝请求，两个实例均不执行错误目标的操作

#### Scenario: 切换 tab 时收到后台事件
- **WHEN** 用户当前显示 B #1 而 A #1 产生审批或输出
- **THEN** 事件只更新 A #1 的状态，不替换 B #1 的当前内容或执行目标

### Requirement: 停止接管与关闭
系统 SHALL 提供停止 Agent、恢复人工输入和关闭 tab 的明确流程。关闭或停止 MUST 先禁止新的自动命令，再取消模型生成和未执行审批；已经发送的命令若不能确认结束，MUST 显示结果未知，不宣称回滚副作用或自动重放。

#### Scenario: 停止等待审批的智能体
- **WHEN** 用户停止仍在等待审批的任务
- **THEN** 该任务未执行的审批失效，晚到的批准无法执行命令，人工输入恢复至已确认安全的终端状态

#### Scenario: 关闭忙碌连接
- **WHEN** 用户关闭包含运行中 AI 命令或 SFTP 传输的 tab
- **THEN** 系统要求确认，确认后停止该连接的新任务并释放资源；历史保留，其他 tab 不受影响，无法判定的远端结果被明确标注

### Requirement: 断线重连
终端会话结束（服务端回收、远端关闭）或连接中断后，系统 SHALL 将所属 tab 置为断线终态：在终端内展示断线原因与重连指引，清空已失效的会话标识使后续输入不再路由到死会话（避免逐帧错误风暴），并提供两个手动重连入口：终端内按 `r`/`R` 键（对标 MobaXterm）与工具栏“重连”按钮（对标 FinalShell）。系统 MUST NOT 自动重连：重建会话会丢失工作目录与运行中程序，上下文切换 MUST 由用户显式确认。重连 SHALL 复用既有连接链路重新发起会话建立，并 MUST 连带重建 AI 与审批通道（三条通道同源拉起：整条连接断开后若不一并恢复，Agent 提问与审批会在重连后静默失效），新会话标识 MUST 覆盖旧值并被后续输入、审批与 AI 路由采纳；已渲染的终端历史 MUST NOT 因重连被清空。重连发起时系统 MUST 同时重置该 tab 绑定的 Agent 对话记忆：先打断旧对话的在飞回合（沿停止链路由后端中断模型流、使未执行审批失效、终止任务执行；若重连瞬间 AI 通道尚未恢复，打断指令 MUST 在通道恢复后补发，确保旧回合不因时序缺口漏断）并解除其生成中状态，再解绑当前对话使下一次提问在全新对话上推进——新建终端会话是工作目录与环境全部归零的全新 Shell，沿用旧对话会让模型携带与实况脱节的幻觉上下文，而旧回合不被终止会继续占用会话执行槽、阻塞新会话的提问；已产生的对话记录 MUST NOT 被删除，仍可在历史中查阅。

#### Scenario: 空闲回收后重连
- **WHEN** 终端会话被服务端空闲回收下发关闭事件，用户在断线提示后按 `r` 或点击“重连”按钮
- **THEN** 系统重新建立会话并采纳新会话标识，终端继续可用且原屏幕历史保留；新会话为全新 Shell（目录重置为登录目录），断线提示行向用户明示这一边界

#### Scenario: 断线态输入拦截
- **WHEN** 会话已终结时用户在终端继续键入
- **THEN** 除重连快捷键 `r`/`R` 外其余输入被丢弃，不向已失效会话发送任何字节，终端不出现“会话不存在”错误刷屏

#### Scenario: 连接中断后手动恢复
- **WHEN** WebSocket 连接整体断开（如后端重启）后恢复重连
- **THEN** 系统展示断开提示并等待用户触发；触发后重建连接与终端会话，期间不提供自动重试，用户可选择忽略断线提示改而关闭 tab

#### Scenario: 重连重置 Agent 对话记忆
- **WHEN** 用户在该 tab 已与 Agent 对话（含回合正在执行或等待审批）后经历断线并触发重连
- **THEN** 旧对话的在飞回合被打断、未执行的任务与审批终止，该 tab 的 Agent 对话绑定被清空并向用户展示重置注记行，下一次 Agent 提问在全新对话上推进且不再被「本会话正在处理上一条提问」阻塞；旧对话记录保留在历史中可查，未产生过对话的 tab 重连时不出现重置注记

### Requirement: 终端文本剪贴板集成
系统 SHALL 支持用户通过鼠标选择终端文本并复制到系统剪贴板，以及从剪贴板粘贴内容到终端输入。系统 SHALL 提供自定义右键菜单，包含「复制」和「粘贴」按钮。Ctrl+C 快捷键 SHALL 智能分流：有文本选中时复制到剪贴板，无选中时保持原有中断行为（Shell 模式发送中断信号、Agent 模式打断回合）。Ctrl+V 快捷键 SHALL 直接将剪贴板内容作为终端输入发送。

#### Scenario: 鼠标拖选复制文本
- **WHEN** 用户在终端中按住鼠标左键拖选一段文本
- **THEN** 选中文本被高亮显示，右键菜单「复制」按钮可用，点击后将选中内容写入系统剪贴板

#### Scenario: 右键粘贴
- **WHEN** 用户在终端无选中文本区域右键单击
- **THEN** 弹出自定义菜单，「复制」按钮禁用，「粘贴」按钮可用；点击「粘贴」后剪贴板内容作为终端输入发送到 PTY

#### Scenario: Ctrl+C 有选中时复制不中断
- **WHEN** 用户已选中一段终端文本并按下 Ctrl+C
- **THEN** 选中内容被复制到系统剪贴板，不向远端发送中断信号，Agent 回合不被打断

#### Scenario: Ctrl+C 无选中时保持中断
- **WHEN** 终端无文本选中时用户按下 Ctrl+C
- **THEN** Shell 模式下向 PTY 发送 `\x03` 中断信号，Agent 模式下打断当前回合，行为与本变更前完全一致

#### Scenario: 右键菜单样式与交互
- **WHEN** 自定义右键菜单被打开
- **THEN** 菜单使用深色主题（与终端背景一致），跟随鼠标点击位置定位，点击菜单外区域自动关闭，不遮挡终端内容

### Requirement: 剪贴板与 Electron 桌面端兼容
上述剪贴板功能 SHALL 在 Electron 打包环境正常工作。自定义右键菜单 MUST NOT 被 Electron 原生菜单或 CSP 策略拦截。

#### Scenario: 打包版复制粘贴
- **WHEN** 用户在 Electron 打包版中执行鼠标选择和右键复制
- **THEN** 行为与开发版 Web 形态一致，内容正确进入系统剪贴板
