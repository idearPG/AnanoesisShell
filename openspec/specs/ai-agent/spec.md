# AI 智能体规格

## Purpose

提供面向 Linux 运维的智能体能力：理解用户的自然语言意图，借助一组运维工具在目标服务器上收集信息、提议操作，并在人工审批的约束下推进多轮对话，全程以透明、可控的方式协助排障。

## Requirements

### Requirement: 自然语言意图理解与多轮对话
系统 SHALL 允许用户以自然语言描述运维目标，智能体据此在多轮对话中逐步推进，并在同一对话内保留上下文。连接型对话 MUST 绑定具体连接实例；同一 tab 内可识别的人工命令及结果 SHALL 与 Agent 对话共同形成近期上下文，按 agent-context 规格的最近 60 条及 token 预算控制，不自动混入其他连接的历史。

#### Scenario: 用户提出运维请求
- **WHEN** 用户用自然语言描述一个排障目标
- **THEN** 智能体给出分析并决定下一步（收集信息或提议操作），所有远端执行限定在当前绑定连接

#### Scenario: 多轮上下文延续
- **WHEN** 用户在同一会话中追问或补充信息
- **THEN** 智能体基于仍在记忆窗口及 token 预算内的此前对话与操作结果继续回应，历史已退出窗口时不假装仍掌握其内容

#### Scenario: 引用人工操作结果
- **WHEN** 用户在当前连接执行完一条可识别的 Shell 命令，随后问 Agent 刚才的结果说明什么
- **THEN** Agent 能引用该连接内记录的命令结果，标注历史结果而非伪装成新执行，不主动读取其他 tab 或 SFTP 文件正文

### Requirement: 运维工具集

系统 SHALL 向智能体提供一组运维工具，至少包含只读类工具（列目录、读文件、查看系统信息）与命令执行类工具；每次工具调用的参数与结果 MUST 对用户可见。`read_file` 工具 SHALL 支持可选的 `start_line` 和 `end_line` 行范围参数，允许模型按需读取文件的指定行区间。当无范围读取达到行数上限时，系统 SHALL 自动附加结构摘要（文件总行数、头部 20 行、尾部 10 行、导航提示），引导模型使用行范围参数分段读取。

#### Scenario: 调用只读工具收集信息

- **WHEN** 智能体为分析问题需要查看目录、文件或系统信息
- **THEN** 系统执行对应只读工具并将结果回喂给智能体

#### Scenario: 提议执行命令

- **WHEN** 智能体判断需要在服务器上执行某条命令
- **THEN** 系统不直接执行，而是转入命令审批流程

#### Scenario: 分块读取大文件指定行范围

- **WHEN** 智能体调用 `read_file` 并指定 `start_line=100` 和 `end_line=200`
- **THEN** 系统只返回第 100 至 200 行的内容，结果头部标注 `[行 100-200 / 总 Z 行]`（Z 为文件总行数）

#### Scenario: 无范围读取大文件触发自动摘要

- **WHEN** 智能体调用 `read_file` 不指定行范围，且文件行数达到 `read_file.max_lines` 上限
- **THEN** 返回结果包含：文件总行数、前 20 行内容、末尾 10 行内容、截断提示（含中间省略行数和行范围参数使用引导）

#### Scenario: 小文件不触发摘要

- **WHEN** 智能体调用 `read_file` 读取一个行数未达上限的小文件
- **THEN** 返回完整文件内容，不附加摘要信息，行为与本变更前一致

### Requirement: 工具分级执行策略

系统 SHALL 区分只读工具与有副作用的工具：只读工具可自动执行；任何有副作用的工具（如执行命令）MUST 先经人工审批方可执行。`read_file` 带行范围参数时仍为只读工具，自动执行。

#### Scenario: 只读工具自动执行

- **WHEN** 智能体调用只读工具（含带行范围参数的 `read_file`）
- **THEN** 系统自动执行而无需人工审批

#### Scenario: 副作用工具须审批

- **WHEN** 智能体调用有副作用的工具
- **THEN** 系统在执行前进入人工审批流程，未获批准不得执行

### Requirement: 手动工具执行控制

系统 SHALL 由自身控制工具的执行时机，MUST NOT 在未经既定分级策略（只读自动、副作用审批）允许的情况下自动执行智能体请求的工具。

#### Scenario: 拦截待审批工具

- **WHEN** 智能体请求执行一个有副作用的工具
- **THEN** 系统拦截该请求、暂不执行，等待审批结果

### Requirement: 操作透明性
系统 SHALL 在同一终端工作区展示智能体的分析说明与每一次工具调用（工具名、参数、实际命令、结果或拒绝状态），使操作可追溯；模型流式文本、PTY 原始输出和审批状态必须有明确归属，执行输出不得因两条事件通路重复显示。

#### Scenario: 展示工具调用
- **WHEN** 智能体调用任一工具
- **THEN** 界面在所属连接的终端记录流中展示该工具的名称、参数与执行结果或拒绝状态，并能区分分析、待审批与实际执行

### Requirement: 连接级执行互斥与工具幂等保护
系统 MUST 对每个连接的人工和自动输入进行仲裁，同一连接同一时刻只运行一个 Agent 任务；不同连接允许并行。工具执行 MUST 绑定稳定运行标识及调用标识，在重复事件、恢复和重启时不得自动重放已领取或可能已执行的命令。

#### Scenario: 两个连接分别执行任务
- **WHEN** 同一服务器的 A #1 和 A #2 分别提交 Agent 请求
- **THEN** 两个连接各自处理自己的上下文和输入，不能因服务器相同而共享命令队列或互相覆盖审批

#### Scenario: 重复事件与结果未知
- **WHEN** 同一工具调用的执行请求重复到达，或进程恢复时发现已发送但没有确定结果的调用
- **THEN** 系统返回已有状态或明确结果未知，不再次向 PTY 写入该命令

### Requirement: 受控停止任务
系统 SHALL 支持停止当前 Agent 任务，并清算模型流、未执行工具与审批；停止确认之后到达的旧事件不得继续触发工具执行。停止不保证撤销已经发生的远端副作用。

Agent 模式下用户按 Ctrl+C MUST 打断在飞回合，体验对标 Shell 模式 Ctrl+C 打断程序：前端在当前 tab 终端写入 `^C` 留痕并经 AI 通道上行 `stop_turn` 帧（携带 conversation_id），随后 MUST 立即本地闭环（复位生成态、写停止注记行），不依赖后端收尾帧送达；后端命中在飞回合时中断工作线程并以带停止注记的 final 帧尽力收尾（收尾前 MUST 清除线程中断标志，否则 Tomcat WS 发送会被打断导致丢帧），收尾帧若送达对前端是幂等的；未命中时静默忽略（停止是幂等通知，不返回错误帧）。

停止 MUST 穿透到远端与工具回喂层，不得半途被吞：①命中在飞回合时，除中断工作线程外，系统 MUST 经该回合绑定的连接会话定位命令调度器，对其正在执行的远端命令发送中断（否则远端长任务会在本地停止后继续跑）；②系统 MUST 维护不依赖线程中断标志的权威停止状态（回合进行中的轮首、每次工具调用前、流式增量处理时均据此终止），因为工具回退/审批回退会把 InterruptedException 吞成普通失败、导致中断丢失后回合按上一步继续推进；③停止 MUST NOT 被伪装成工具失败结果（tool_result 错误态）回喂给模型——一旦回喂，模型会把"用户停止"当作"这条命令失败了，换条路重试"，正是"停不下来"的症状。

#### Scenario: 生成中停止并切回人工
- **WHEN** 用户停止正在生成的任务并切回 Shell
- **THEN** 模型生成终止、未执行工具失效，终端在状态确认后归还人工输入权，保留已发生操作及结果记录

#### Scenario: Agent 生成中 Ctrl+C 即时打断
- **WHEN** Agent 回合在飞（思考/工具循环中）用户在当前 tab 终端按 Ctrl+C
- **THEN** 终端立即可见 `^C` 留痕与停止注记行（如「本轮处理已被用户停止。」），生成态本地立即复位、输入区恢复可用，即使后端收尾帧因连接中断未送达；若回合恰已自然结束，`stop_turn` 被忽略且已有输出不受影响

#### Scenario: 停止穿透打断远端在飞命令
- **WHEN** Agent 回合正阻塞在一条已批准、在远端 PTY 执行的命令上，用户停止该回合
- **THEN** 系统向该连接会话的调度器发出对在飞命令的中断，远端输出被截断；停止不以 tool_result 错误态回喂模型，回合不再推进到下一轮工具循环

#### Scenario: 工具阶段被中断不被回退层吞没
- **WHEN** 停止信号落在只读工具执行或审批回退等待期间（该路径历史上会把中断转成普通失败）
- **THEN** 系统据权威停止状态在下一个检查点终止回合并收尾停止注记，用户看到停止而非红字报错或继续执行

### Requirement: 单回合工具调用轮次上限
系统 MUST 限制单个用户回合内的工具调用循环轮数上限为 **30 轮**（用户反馈原 8 轮过低、真实排障任务动辄十几步被拦腰截断；上限存在的目的是防模型死循环永久占用工作线程，而非限制正常任务）。触顶时系统 MUST 向用户输出明确说明（含上限轮数）并落库，不得悄悄结束；用户可继续提问推进。

#### Scenario: 达到轮次上限明确收尾
- **WHEN** 单回合工具循环用满 30 轮仍未自然完成
- **THEN** 终端收到含“上限 30 轮”字样的收尾说明且该说明落库，刷新后仍可见；回合占用的工作线程与输入权正常释放

### Requirement: 会话当前工作目录感知
系统 SHALL 追踪每个连接终端会话的当前工作目录（来自 Shell 集成产生的 CWD 帧，无论源于人工 cd 还是 Agent 命令），并在构建智能体系统提示时注入该目录；目录未知（尚未收到任何 CWD 帧）时 MUST 不渲染该上下文而非给空路径。上下文超限恢复重建提示时同样适用。

#### Scenario: 用户 cd 后询问当前目录
- **WHEN** 用户在 Shell 模式 cd 到某目录后切到 Agent 问“列出当前目录的文件”
- **THEN** 智能体按注入的真实工作目录理解“当前目录”，工具调用默认基于该路径而非根目录

#### Scenario: 尚无工作目录证据时不注入
- **WHEN** 会话建立后尚未产生任何 CWD 帧（或会话未绑定终端）
- **THEN** 提示词不包含工作目录小节，智能体需自行用只读工具（如 pwd）取证

### Requirement: 人工命令记忆同步
系统 SHALL 将用户在 Shell 模式下手动执行的每一条可识别命令（经 Shell 集成帧协议解析出 CMD_START + CMD_END 的命令）持久化到当前 tab 对应的对话历史中（`source=shell_event`），内容包括命令原文、退出码与输出摘要。Agent 构建上下文时 SHALL 将这些记录与 AI 消息共同纳入模型输入，使模型能引用用户手动执行过的命令及结果。

#### Scenario: 人工命令自动进入 Agent 上下文
- **WHEN** 用户在 Shell 模式执行一条命令（如 `ls -la /tmp`）并产生 CMD_END 帧
- **THEN** 该命令的原文、退出码与输出摘要作为 `source=shell_event` 消息写入当前对话历史，后续 Agent 回合的上下文历史中包含此记录

#### Scenario: 全部人工命令无过滤记录
- **WHEN** 用户在 Shell 模式连续执行多条命令（`cd /opt`、`docker ps`、`cat config.yml`）
- **THEN** 每条命令均有对应的 `shell_event` 记录写入对话历史，不做内容过滤或去重

#### Scenario: 人工命令输出截断
- **WHEN** 人工命令输出超过摘要上限（如 `cat` 一个大文件）
- **THEN** 写入对话历史的输出摘要被截断并标注截断标记，原始完整输出仍存于 `command_executions` 表

### Requirement: 系统提示词注入最近 Shell 活动
`AgentSystemPrompt` 构建系统提示时 SHALL 包含一个“最近 Shell 活动”段落，列出当前会话最近若干条人工命令的命令原文与退出码，使模型在回答前即可感知用户在 Shell 中做了什么。无最近活动时该段落不渲染。

#### Scenario: 有最近 Shell 活动时注入活动摘要
- **WHEN** 用户最近在当前连接执行了若干命令后切到 Agent 模式提问
- **THEN** 系统提示包含“最近 Shell 活动”段落，列出命令原文与退出码

#### Scenario: 无 Shell 活动时不渲染
- **WHEN** 当前连接尚无任何人工命令记录
- **THEN** 系统提示不包含“最近 Shell 活动”段落

### Requirement: 嵌套 Shell 环境感知
系统 SHALL 检测用户是否进入了嵌套 Shell 环境（如通过 `docker exec -it <container> bash` 进入容器），并在 Agent 系统提示中注入该环境状态。嵌套检测由 `PtyCommandScheduler` 的帧超时探测机制驱动；检测到嵌套环境后，系统提示 SHALL 告知模型当前可能处于嵌套 Shell（如 Docker 容器）中。

#### Scenario: 检测到嵌套 Shell 后注入提示
- **WHEN** 嵌套 Shell 探测机制确认用户进入了嵌套环境（探测标记回显匹配）
- **THEN** Agent 系统提示包含嵌套环境说明（如“用户终端当前可能处于 Docker 容器或嵌套 Shell 中”），模型据此调整命令建议

#### Scenario: 嵌套 Shell 降级后仍注入提示
- **WHEN** 嵌套 Shell 集成重安装失败、降级为 exec 通道模式
- **THEN** 系统提示仍包含嵌套环境说明，同时告知模型 Shell 集成不可用、工具可能无法正常工作

#### Scenario: 未检测到嵌套环境时不渲染
- **WHEN** 用户始终在初始 Shell 中操作，未进入任何嵌套环境
- **THEN** 系统提示不包含嵌套环境段落
